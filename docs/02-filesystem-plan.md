# Filesystem resource and transport plan

## Current state

`offs/crates/file-system/src/file_system.rs` owns file paths, metadata in `metadata.redb`, and content under `.data/`. Its metadata is KV snapshots (including tombstones); its file sessions handle content and operations separately (`src/sync.rs`, `src/transport.rs`). `Transport` and `FileSessionService` are the existing integration seam. `of/crates/storage-service/src/scoped_file_system.rs` currently opens a local filesystem per `(user_sub, application_id)` and sets root residency to Full. It does not issue a database. `offs` imports `ofdb`'s KV primitives via sibling paths; it does not use `ofdb`'s SQL database engine to replicate file metadata.

## Work

1. **Expose filesystem resources through the `of` storage API.** Allow multiple filesystems per owning user/application, each with its own stable Filesystem ID and optional non-unique name. An application client exchanges its user token for a normal storage-audience access token to create/open/list/delete. Only the owner changes path-subtree grants. `ofdb` syncs the resource catalog for discovery and deletion status; `file-system` owns paths, bytes, policy and sync. Do not treat `FileMeta.owner`, residency or endpoint identity as permission. Rename old `VaultId` to Filesystem ID in types, callers and docs; the ID identifies one instance and its local root, not a separate vault concept.
2. **Implement the Iroh transport adapter in `offs`.** `iroh-chain` owns filesystem ALPNs and routing; `file-system` implements `Transport` and `FileSessionService` over it with bounded versioned metadata messages and direct file streams. Bind requests to Filesystem ID, approved remote endpoint, device selection and current granted subtree. Send only authorized subtree metadata/content plus minimal ancestor directory names, never sibling entries. Enforce incoming and outgoing scope even when a peer is paired. `file-system` owns metadata reconciliation, content revision, provider choice and residency; do not funnel bytes through DB row sync or mesh notifications.
3. **Sync authorized filesystem data except locally omitted Passthrough bytes.** Authorized peers receive scoped metadata, tombstones and policy; Full peers store authorized content while Passthrough peers read from Full peers without storing content or writing. Owner-only grant operations must converge offline: concurrent revoke beats grant on the same subject/path; a causally later re-grant restores access. A single mutable KV ACL value is not sufficient (`ofdb` KV rejects divergent same-generation snapshots); specify and test an operation-based or equivalent causal policy representation. Token issuance may use local stale policy: remote revocation applies after sync, and existing tokens/connections until expiry/close. Residency stays local. Test offline providers, stale revisions, canceled reads, restart and lag recovery.
4. **Reconcile obsolete contracts.** Remove obsolete hash-backed/folder-document FS and OAuth tunnel descriptions; `offs` uses stable file IDs and KV snapshots. `of/crates/idp-server/Cargo.toml` points to missing `offs/crates/iroh-chain*`; wire `ofnet` plus the `offs` adapter and delete stale helpers. Remove old-format migration/legacy handling; incompatible `metadata.redb` must fail clearly without automatic deletion, with documented operator removal.
5. **Support the sibling checkout.** Keep the existing `ofdb` KV path dependencies in `offs/crates/file-system/Cargo.toml`, document the sibling directory layout and test it. Do not duplicate KV or depend on the root SQL API. Check downstream users before deleting empty `in-memory`, `native` and `sync` feature flags.

## Acceptance checks

- A filesystem and database issued to the same principal have separate IDs and permissions; FS sync can succeed without DB sync and vice versa.
- Authorized peers reconcile subtree metadata, policy and tombstones; folder-only grantees see no sibling entries or bytes. Remote content is fetched only when a Full peer is available; Passthrough is read-only. Rename/move into and out of a granted path updates access after policy convergence; grants bind to normalized paths, not stable file IDs.
- Offline concurrent owner grant/revoke converges with revoke winning; causally later re-grant restores access. Reconnect, stale token policy, corrupt/oversized messages and incompatible metadata format have explicit tested outcomes. Existing `offs/crates/file-system/tests/file_system.rs` tests still pass; add a real Iroh adapter/consumer integration test and run `cargo hack test --feature-powerset --all-targets` in `offs` and `ofnet`.
