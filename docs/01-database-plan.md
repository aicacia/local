# Database resource and replication plan

## Current state

`ofdb` owns transactional SQL-like rows and a distinct KV stack. Its current sync code is in `ofdb/crates/sync/src/{protocol,session,transport}.rs`: `SyncMessage` carries hello/manifest/inventory/state/changes/recovery, and `SyncTransport` is the network abstraction. `ofdb/src/api.rs` re-exports the sync API with the `sync` feature. `of/crates/db/src/native.rs` opens a database for IdP/management repositories. That control-plane database is not an application filesystem or an application database issued by storage.

`ofdb/CONTEXT.md` describes state-unit/manifests and incremental payloads. `ofdb/docs/design.md` and parts of `of` setup documentation still describe checkpoint/envelope/frontier APIs. Confirm actual supported sync behavior and rewrite the outdated descriptions; do not add an envelope adapter solely to keep the old setup flow working.

## Work

1. **Expose database resources through the `of` storage API.** Allow multiple DBs per owning user/application, each with a distinct stable ID and optional non-unique display name. Create/open/list/delete require a normal storage-audience access token exchanged from an application client's user token. Only the owner edits whole-DB read/write grants; the resource catalog is synced via `ofdb` for discovery and replicated deletion tombstones. SQL-like and KV behavior belong to this DB model, not third-party resource types. Keep the IdP/control-plane DB separate from application DBs; filesystem grants cannot authorize a DB.
2. **Wire the supported sync contract inside `ofdb`.** `iroh-chain` owns the DB ALPN; `ofdb` implements the framed `SyncTransport` adapter (`Server::connect_direct(id, alpn)` is the current hook). Sync all durable SQL-like/KV state; verify actual APIs for each rather than assuming one session covers both. An approved endpoint alone is insufficient: bind incoming sessions to the DB ID, the user's selected resource, a valid whole-DB grant and read/write scope. An authorized device receives the whole database, not row-level subsets. Retry with a manifest after reconnect and test interrupted import; keep control-plane and application DB grants separate.
3. **Fix installation join.** `of/apps/app/src-tauri/src/setup.rs` calls `/setup/devices` and `/setup/sync` and imports `frontier_bytes`, `import_checkpoint_bytes` and `import_envelope_bytes`, but those exports, contracts and server routes are not present in the inspected tree. Replace that path with a tested authenticated control-plane DB bootstrap on the actual `ofdb` sync API. Do not route control-plane records through filesystem sync or claim setup complete before authoritative DB state is committed.
4. **Keep `iroh-chain` transport-only.** `ofnet/crates/iroh-chain/src/server.rs` currently registers `metadata/1` and `transfer/1` and hardcodes `TRANSFER_ALPN` in `open_stream`. Its owner should register/route a DB ALPN and expose direct streams without file-specific defaults, deleting replaced helpers after migration. `ofdb` owns DB codecs, recovery and sync; the storage API owns client token policy. Mesh `send` is not a durable delivery acknowledgement.
5. **Retire obsolete DB docs/paths after cutover.** Reconcile `ofdb/docs/design.md` and `ofdb/docs/goal.md` with implemented sync APIs and current `ofdb/CONTEXT.md`; remove unsupported checkpoint/envelope terminology and dead setup imports/callers rather than shipping a second replication protocol. Keep `ofdb`'s file-backed database backend: its file is a persistence detail, not `offs` data.

## Acceptance checks

- Multiple databases can be created for one user/application without creating a filesystem; an IdP database join completes after authenticated state sync without exposing it to application-storage peers. Names do not confer identity or access.
- Authorized peers reconcile schema, rows, tombstones and conflicting offline changes; reconnect and restart converge without relying on mesh delivery. Failed/incomplete sync cannot be reported as completed setup.
- Unpaired, unselected, revoked-after-policy-convergence, wrong-resource and read-only peers cannot start unauthorized DB sync or writes; filesystem grants never authorize DB replication. Already-copied data cannot be recalled. Oversized/malformed protocol frames fail safely.
- Focused: `ofdb/tests/{local_sql,cluster_sync,cluster_chaos}.rs`, `ofdb/crates/kv/tests/{backends,replication}.rs`, and new SQL/KV transport and join integration tests. Then run `cargo hack test --feature-powerset --all-targets` and Clippy in affected workspaces.

## Handoff checklist

Dependencies: [roadmap R1–R2](00-storage-split-roadmap.md#handoff-checklist). One agent owns any shared `ofnet` server changes; others should work in `ofdb` or `of` without editing the same files.

- [ ] **D1 — Confirm DB sync API (`ofdb`):** Read `ofdb/crates/sync/src/{protocol,session,transport}.rs` and compare `ofdb/CONTEXT.md` with `ofdb/docs/{design,goal}.md`. Update stale docs to describe only supported state-unit/incremental sync. Done when docs match the exported `SyncTransport`/`SyncMessage` and no advertised checkpoint/envelope API is missing. No new legacy adapter.
- [ ] **D2 — Manage application databases (`of` storage API):** Implement create/open/list/delete for multiple DBs per owner using exchanged storage-audience tokens. Add optional duplicate names, owner-only whole-DB grants and synced catalog entries/tombstones in `ofdb`; distinguish local device deselection from owner deletion. Test restart, independent FS resources, wrong-kind/owner and granted-subject discovery. Done when a client obtains a DB without creating an FS. Depends on R1–R2.
- [ ] **D3 — DB sync over mesh transport (`ofdb`; `ofnet` ALPN owner):** Register/route the DB ALPN; implement bounded `SyncTransport` and SQL-like/KV sync in `ofdb`. Bind every incoming session to endpoint approval, selected DB ID and whole-DB read/write grant before frames; only authorized devices receive DB data. Test paired-only, unselected, stale-policy then converged revocation, wrong-resource, read-only and oversized-frame cases. Done when peers sync durable DB data without filesystem ALPNs or mesh delivery guarantees. Depends on R2 and the shared `ofnet` owner.
- [ ] **D4 — Restore installation join (`of`):** Replace the unsupported checkpoint/envelope calls in `of/apps/app/src-tauri/src/setup.rs` with authenticated control-plane DB sync using D3's actual contract; implement matching server route/contract if needed. Test first join, failed/interrupted join and restart/retry; setup must not complete before durable import. Done when desktop and server compile and join converges without FS access. Depends on D1 and D3.
- [ ] **D5 — Regression gate (`ofdb`, `ofnet`, `of`):** Run targeted SQL/cluster-sync/chaos tests, new issued-DB and Iroh/join tests, `cargo hack test --feature-powerset --all-targets` and Clippy in touched repos. Record passing commands or precise blockers. Depends on D2–D4.
