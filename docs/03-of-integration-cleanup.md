# `of` cutover and deletion plan

This is a breaking migration: remove superseded routes, filesystem-backed control-plane alternatives and stale networking paths once the selected database and filesystem flows pass their tests. Do not preserve old state with glue code.

## Work in order

1. **Implement the two resource APIs and authorization contract.** The storage API allows multiple DBs and FSs per owning user/application through normal storage-audience tokens exchanged from application-client user tokens. Only the owner edits grants; DB grants cover a whole database, FS grants cover normalized path subtrees. Optional duplicate display names never identify a resource. The accepted `of/docs/storage/ARD01.md` describes filesystem WebSocket token exchange and folder-scoped rights, partly implemented in `of/crates/idp-server/src/router/routes/oauth2/token.rs`, `of/crates/idp-service/src/oauth2/service.rs`, `of/crates/idp-server/src/router/storage.rs` and `of/crates/storage-server/src/router/storage_socket.rs`. Define DB-specific rights; a filesystem folder grant must not confer SQL/KV access. [ADR 0001](adr/0001-offline-storage-resources.md) supersedes the historical filesystem ADR's local-only ACL storage and single-filesystem namespace assumptions; preserve that historical record. Keep IdP token issuance separate from resource management.
2. **Fix authorization before cutover.** `of/crates/storage-service/src/authorization.rs` selects a matching rule in reverse lexicographic order, not the longest matching folder path required by `of/docs/storage/ARD01.md`. Align normalization with `of/crates/idp-service/src/oauth2/authorization.rs`. Sync owner-only FS policy with offline concurrent revoke-wins and causal re-grant; do not put it in one mutable KV ACL value. Keep a synced resource catalog for discovery, grants and tombstones; its FS grant view must reflect authoritative `file-system` policy rather than conflict with it. Test nested overrides, rename into/out of granted paths, stale-policy token issuance, invalid paths, cross-kind grants and convergence. Already-issued tokens last until expiry and open connections until close; revocation cannot erase copied data. Avoid logging query-string JWTs.
3. **Replace the old session flow.** `of/README.md`, `of/CONTEXT.md` and `of/docs/idp/ADR01.md` still promise a single-use storage session; `of/crates/management-service/src/hosted_control_plane.rs` still calls `storage/sessions`, and `of/crates/management-service/src/storage_session.rs` / `of/crates/idp-model/src/contract/storage_session.rs` implement that model. Once clients use the selected exchanged-token path, delete the old service, contract, endpoint/callers and unused dependencies; update the docs. Do not offer both protocols for compatibility unless a current client is proven to need a migration window.
4. **Make DB join a separate tested flow.** The desktop `of/apps/app/src-tauri/src/setup.rs` references absent checkpoint/envelope exports, request types and `/setup/sync` routes. Implement installation join using `ofdb`'s supported sync boundary (see [01-database-plan.md](01-database-plan.md)) and remove the unsupported checkpoint/envelope caller. Do not substitute an application filesystem sync for IdP/management DB state. Ensure setup readiness waits for a committed, authorized DB bootstrap.
5. **Delete losing control-plane storage.** Check callers and feature configurations, then remove `of/crates/management-service/src/fs/` and its `fs` feature if the currently wired DB repositories remain authoritative. `of/crates/storage-service/src/global_identity_runtime.rs` is not exported from `storage-service/src/lib.rs`; check its remaining references, then remove it and the `global_identity_*` contracts in `of/crates/idp-model/src/contract/` if no active joining path needs them. Keep local secret/key material out of both replicated application resources.
6. **Repair cross-repo wiring and documentation.** Replace references to missing `offs/crates/iroh-chain*` with `ofnet/crates/iroh-chain` as a transport library. Replace `VaultId` with Filesystem ID across runtime types/docs; bind it to the filesystem instance and local root, not a permission. DB sync lives in `ofdb`, FS sync in `file-system`; no service sync logic belongs in `of`. Remove obsolete storage-session, local-only ACL, folder-document, writable-Passthrough and filesystem-only Iroh descriptions. Document sibling checkout and both APIs.

## Cutover gates

- Run focused token-exchange, folder ACL, storage WebSocket, setup/join and resource-issuance tests. Test a user issued both resource types and deny a database request with a filesystem-only grant.
- Run `cargo check --workspace`, `cargo hack test --feature-powerset --all-targets`, Clippy/format and `just crap` from `of`, then corresponding suites in `ofdb`, `offs` and `ofnet`. Record existing failures separately from regressions; currently missing path dependencies and setup symbols can block `of` builds.
- Verify removed features, modules, routes and obsolete `VaultId` references; incompatible on-disk data must fail clearly and require manual removal, with no migration or automatic deletion.

## Handoff checklist

Depends on [database](01-database-plan.md#handoff-checklist) and [filesystem](02-filesystem-plan.md#handoff-checklist) replacements for any live caller. Work on distinct `of` crates can proceed in parallel; run the workspace gate only after all removals land.

- [ ] **C1 — Correct and replicate FS ACLs (`of/crates/storage-service`, `of/crates/idp-service`, `offs`):** Replace reverse-lexicographic selection with longest normalized folder match; align token-exchange checks. Move local-only `authorization.json` authority to `file-system`'s synced owner-only policy; implement offline revoke-wins and causal re-grant, and project discoverable grants into the `ofdb` catalog without a second ACL authority. Test stale-policy token issuance, two-peer convergence, nested overrides, path rename, invalid paths and DB isolation. [ADR 0001](adr/0001-offline-storage-resources.md) supersedes the local-only ACL decision in historical `storage/ARD01.md`. Done when issuance and FS peer sync agree after policy convergence.
- [ ] **C2 — Retire storage sessions (`of/crates/management-service`, `of/crates/idp-model`):** Trace all callers of `HostedControlPlane::storage_scope` and the `storage/sessions` route. Migrate live callers to the accepted exchanged-token flow, then delete `management-service/src/storage_session.rs`, `idp-model/src/contract/storage_session.rs`, unused route/exports and dependencies. Update `of/README.md`, `of/CONTEXT.md`, `of/docs/idp/ADR01.md` to mark the old path superseded without rewriting the historical ADR. Done when no runtime calls `storage/sessions` and current docs describe one working flow. Depends on C1 and replacement tests.
- [ ] **C3 — Remove filesystem control-plane stores (`of/crates/management-service`, `of/crates/storage-service`, `of/crates/idp-model`):** Search usages and feature combinations; if the DB repositories cover all active callers, delete `management-service/src/fs/`, the `fs` feature and its dependencies, unexported `storage-service/src/global_identity_runtime.rs`, and orphaned `idp-model/src/contract/global_identity_*` contracts. Do not delete a referenced joining path before D4 passes. Done when all remaining control-plane persistence uses the chosen DB path and feature-powerset builds.
- [ ] **C4 — Align consumer integration (`of/crates/idp-server` and runtimes):** Remove missing `offs/crates/iroh-chain*` manifest paths/imports; consume `ofnet` as transport while `ofdb` and `file-system` own sync. Rename `VaultId` to Filesystem ID in active types, callers, route contracts and docs; do not preserve aliases. Bind peer authorization to approved endpoint, selected resource and exact ID/scope, rather than the existing ignored `VaultId`. Remove obsolete tunnel helpers once unused. Test separate DB and folder-scoped FS flows. Depends on D3, F3 and F5.
- [ ] **C5 — Update current documentation (`of`):** Reconcile `of/CONTEXT.md`, README/setup/storage docs with shipped multi-resource APIs, synced resource catalog and FS policy, read-only Passthrough and DB join. Preserve historical ADRs; link [ADR 0001](adr/0001-offline-storage-resources.md) to mark the local-only ACL and one-filesystem assumptions superseded. Document sibling checkout, incompatible-store operator removal, selection versus deletion and revocation latency. Done when current docs promise only implemented routes and sync APIs. Depends on C2–C4.
- [ ] **C6 — Final removal gate (`of`):** Search for old routes/types/features and missing `offs` network paths. Run focused ACL, token exchange, WebSocket, setup/join and two-kind issuance tests; then `cargo check --workspace`, `cargo hack test --feature-powerset --all-targets`, Clippy/format and `just crap`. Record command outcomes and distinguish pre-existing failures. Depends on C1–C5.
